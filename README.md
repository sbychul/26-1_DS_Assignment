# 🏁 Multi-Agent Turn-Based Combat Simulator
> **자바 객체 지향 프로그래밍(OOP)과 다익스트라 알고리즘을 활용한 턴제 전장 시뮬레이터**

본 프로젝트는 자료구조 및 알고리즘 과제를 수행하기 위해 개발된 시스템으로, 전장 그래프 위에서 서로 다른 메커니즘을 가진 두 팀(BLUE, RED)의 유닛들이 자율적으로 최단 경로를 탐색(Dijkstra)하고 이동하며 교전하는 멀티 에이전트 시뮬레이터입니다.

---

## 📂 1. 프로젝트 디렉토리 구조 (Package Structure)
역할과 데이터 모델, 게임 시스템 엔진의 결합도를 낮추고 모듈화를 실현하기 위해 다음과 같이 패키지를 분리하였습니다.

```text
src/
└── DS_Assignment/
    ├── Main.java                      # 프로그램 실행 진입점
    │
    ├── model/                         # 시스템의 데이터 구조 및 모델 레이어
    │   ├── units/                     # 유닛(에이전트) 관련 패키지
    │   │   ├── Team.java              # 소속 팀 및 심볼 지정 (Enum)
    │   │   ├── Unit.java              # 유닛 공통 속성 및 행위 정의 (Abstract Class)
    │   │   ├── Tank.java              # 방어형 유닛 클래스 (자식 클래스)
    │   │   ├── DPS.java               # 공격형 유닛 클래스 (자식 클래스)
    │   │   └── Healer.java            # 지원형 유닛 클래스 (자식 클래스)
    │   │
    │   └── graph/                     # 전장 맵 네트워크 자료구조 패키지
    │       ├── NodeName.java          # 11개 전장 정점 정의 (Enum)
    │       ├── Graph.java             # 무방향 가중치 인접 리스트 그래프
    │       └── Dijkstra.java          # 동적 가중치 기반 최단 경로 알고리즘
    │
    └── engine/                        # 시뮬레이터 제어 및 스케줄러 레이어
        └── SimulatorManager.java      # 라운드 제어, 리스폰 큐 관리 핵심 엔진
```

## 🛠️ 2. 핵심 클래스별 역할 설명 (Core Classes)
### 👥 Model - Units 파트
* Team (Enum): ```A(BLUE), B(RED)``` 팀을 정의하며, 각 팀의 고유 텍스트 심볼(🔵, 🔴)을 캡슐화하여 로그 가독성을 높였습니다.
* Unit (Abstract Class): 체력, 공격력, 현재 위치 등의 상태와 move, takeDamage, heal 등 공통 행위를 정의한 최상위 클래스입니다. ```act(Unit target)``` 추상 메서드를 통해 자식들의 다형성을 보장합니다.
* Tank / DPS / Healer: Unit을 상속받아 구현된 구체 클래스들입니다. 명세에 지정된 독립 베르누이 시행(명중률) 기반의 기본 공격, 치명타 패시브, 아군 치유 분기 메커니즘이 ```act()``` 내부에 독립적으로 구현되어 있습니다.

### 🗺️ Model - Graph 파트
* NodeName (```Enum```): 명세서의 11개 노드(```SpawnA, P, TL``` 등)를 정의합니다. 정적 타입 안정성을 확보하고 동점 처리 시 사전 순 비교(```compareTo```)가 즉시 가능하도록 유도했습니다.
* Graph: 인접 리스트 구조로 맵의 연결 관계를 불변 상태로 유지합니다. 상대 유닛의 점유 상태에 따라 진입 위험도 가중치(기본 1, 적 배치 시 +2)를 연산하는 ```getDynamicWeight()``` 기능을 포함합니다.
* Dijkstra: ```PriorityQueue```와 ```EnumMap```을 결합한 최적화된 최단 경로 알고리즘입니다. 명세 필수 조건인 '경로 비용 동률 발생 시 노드 ID 사전 순 오름차순 결정(Tie-break)' 규칙을 처리합니다.

### ⚙️ Engine 파트
* ```SimulatorManager```: 전체 시뮬레이션의 핵심입니다. 지정된 턴 순서 스케줄링 제어, 라운드 시작 시 힐러 패시브 발동, 사망 유닛 FIFO 리스폰 큐(```LinkedList```) 적재, 그리고 거점 소유권 유무에 따른 점령 진척도 틱 연산을 총괄합니다.

## ✨ 3. 주요 설계 특징 및 기술적 초점 (Technical Highlights)
1. Single Source of Truth (단일 진실 공급원) 원칙 준수
    유닛의 생사 여부를 별도의 ```boolean``` 필드로 중복 관리하지 않고, ```isAlive()``` 메서드가 상시 ```hp > 0```을 동적으로 판단하게 함으로써 상태 불일치 버그(체력이 0인데 생존 등)를 차단했습니다.


2. EnumMap 기반의 메모리 및 탐색 최적화
    그래프 인접 리스트 및 다익스트라 테이블의 자료구조로 일반 ```HashMap``` 대신 자바의 ```EnumMap```을 채택했습니다. 대형 해시 연산 없이 가볍고 빠른 배열 인덱싱 매핑으로 동작하므로 성능 향상을 실현했습니다.


3. 방어적 복사(Defensive Copying)를 통한 불변성 유지
    외부 알고리즘 클래스가 원본 맵 구조를 오염시키는 것을 막기 위해, ```Graph.getNeighbors()``` 호출 시 ```Collections.unmodifiableList()```로 감싸 수정 불가능한 View를 제공하도록 설계했습니다.


4. 동적 가중치와 순수 홉(Hop) 거리의 결합
    딜러/힐러는 적의 유무를 감지해 위험도를 계산하는 반면, 탱커는 가중치를 전면 무시합니다. 다익스트라 내부 엔진에 ```ignoreWeight``` 플래그를 두어 하나의 알고리즘 함수로 다채로운 유닛별 이동 전략을 구현했습니다.

## 🏃 4. 실행 방법 (How to Run)
1. 자바 IDE(IntelliJ IDEA 또는 Eclipse)에서 본 프로젝트를 엽니다.

2. ```DS_Assignment.Main``` 클래스를 찾아 실행(```Run```)합니다.

3. 콘솔창에 0.5초 간격으로 출력되는 라운드별 전황 로그와 최종 승리 팀 리포트를 확인합니다.
